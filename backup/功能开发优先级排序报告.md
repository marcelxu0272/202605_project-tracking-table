# 功能开发优先级排序报告

> **用途：** 面向开发节奏紧张阶段的交付优先级指导，用于拆分开发顺序和里程碑验收
> **最后更新：** 2026-06-10
> **配套文档：** [需求文档（产品版）](./需求文档_产品版.md) · [需求文档（开发版）](./需求文档_开发版.md)

---

## 1. 排序原则

优先级以**业务功能链路是否可跑通**为主轴，而不是按角色。角色（系统管理员、板块管理员等）只是功能的承载视角，不作为排序依据。

**总体策略：**

1. 先把"数据能显示、能编辑、能保存、系统字段能关联"这层打通（P0）
2. 再把"管理员能运营系统、能完成周期归档"这层打通（P1）
3. 然后完成"板块填报 → 提交审批"这条主链（P2）
4. 再完成"审批通过/驳回 → 状态流转"的闭环（P3）
5. 最后扩展"项目经理个人填报"能力（P4）
6. 预警管理与邮件提醒属于运营辅助，排到最末（P5）

**项目详情 Drawer 的处理：** Drawer 内的基础字段查看与编辑随 P0 主表一起可用，但 Drawer 内的深度功能（工时/成本统计展示、预警标签、WIP 折叠动效等体验增强）划至 P5。

---

## 2. 优先级总览

```
P0  数据底座与主表基础可用          ← 核心依赖，必须最先完成
P1  系统运营配置与归档能力
P2  填报管理主链路（板块级）
P3  审批闭环能力
P4  项目经理个人填报扩展
P5  次要增强（预警、邮件、Drawer 深度体验）   ← 最末
```

各优先级之间存在依赖关系：

```
P0 → P1 → P2 → P3
          └────────→ P4
P2/P3 完成后才涉及 P5
```

## 3. P0 — 数据底座与主表基础可用

**目标：** 系统管理员打开主表（项目追踪表）后，能看到数据、能编辑保存、系统字段能关联更新。这是整个系统的运行基础。

### 3.1 主表加载与渲染

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| Luckysheet 初始化 | 83 列字段字典加载、行布局（小计/合计/分类/数据行）、列宽配置 | `js/views/ProjectEditor.js`、`config/fields/fields-data.js` |
| 表头冻结与分区色 | 冻结至项目号列左侧；可编辑列浅黄、只读列灰白 | `js/field-config.js` |
| 公式引擎初始化 | auto_calc 字段（N/O/P/Q/R/S 等）在加载后触发重算 | `js/formula-engine.js` |
| 数据加载 API | `GET /api/projects`；bootstrap 含字段字典与 meta | `server/index.js`、`server/db.js` |
| 角色数据范围过滤 | 系统管理员看全量；按 `unit_code` 板块过滤；PM 按项目绑定关系 | `server/index.js` |

**最小验收：** 系统管理员登录后打开项目追踪表，Luckysheet 正常渲染全量项目与 83 列字段，公式列（R/S/N/O/P 等）有计算结果，合计行有数值。

### 3.2 单元格编辑与保存

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| 字段权限控制 | `system_sync`（系统管理员可编辑）、`manual_input`（多角色可编辑）、`auto_calc`（只读）；锁定期内除系统管理员外只读 | `js/field-config.js` |
| 单元格自动保存 | 失焦后自动保存，`PUT /api/projects/:id` | `js/views/ProjectEditor.js` |
| 手动保存 | 工具栏「保存」按钮，全表同步；提交前兜底保存 | `js/views/ProjectEditor.js` |
| 月度时间窗 | 月度完成额仅报告月及之后可写，之前历史只读 | `js/field-config.js`、`server/index.js` |
| 锁定状态计算 | `lockStatus`（open/locked）按报告日与锁定日计算；锁定期非管理员只读 | `server/db.js`、`js/store.js` |
| 金额字段格式化 | 千分位显示，输入时去千分位转数值 | `js/formatters.js` |
| 日期字段规范化 | Excel 序列号/对象/文本统一转 YYYY-MM-DD 入库 | `js/views/ProjectEditor.js` |

**最小验收：** 系统管理员编辑任意 `manual_input` 列单元格后失焦，刷新页面后数值保留；`auto_calc` 列不可编辑；锁定期内其他非管理员视角呈只读。

### 3.3 系统字段关联更新（数据同步）

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| 手动刷新数据 | 系统管理员点击「刷新数据」→ `POST /api/editor/refresh-data`：① 平台引用同步（新增项目、`_system_ref`、报告月 MI/MP）；② 重载最新库项目 payload | `server/platform-sync.js`、`server/index.js` |
| 每日自动同步 | 每日 02:00 定时执行相同逻辑；锁定期暂停 | `server/platform-sync.js` |
| 管理员覆盖标记 | 管理员手动修改系统引用列后写 `_system_override`；刷新时不再覆盖 | `server/platform-sync.js` |
| A 列新/旧项目 | 根据 CRB 合同状态自动取值 | `server/platform-sync.js` |
| 合同额区（N/O/P） | 含税/不含税合同额、税率计算；N/T 仅系统管理员可改 | `js/formula-engine.js`、`server/index.js` |

**最小验收：** 系统管理员点击「刷新数据」后，平台模拟数据写入 `_system_ref`，新增项目号出现在主表中；管理员覆盖后刷新不丢失覆盖值。

### 3.4 初始化导入

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| Excel 导入 SQLite | 启动时 `初始数据.xlsx` 自动导入；管理设置「从初始 Excel 恢复」手动重导 | `server/xlsx-seed.js`、`server/index.js` |

**最小验收：** 启动服务后主表有项目数据；「从初始 Excel 恢复」可重导；重置开发环境后演示数据正确还原。

### 3.5 变更高亮与 baseline diff（基础层）

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| 相对 baseline 变更高亮 | 字段值与 `baselineVersion` 快照对比，变更格浅橙 + 左边框 | `js/baseline-diff.js`、`js/change-meta.js` |
| 新增项目行标记 | 相对 baseline 新增的项目行浅绿底色 | `js/baseline-diff.js` |

**最小验收：** 系统管理员修改字段后保存，对应单元格显示橙色高亮和批注；相对 baseline 新增的项目行显示绿色底色。

## 4. P1 — 系统运营配置与归档能力

**目标：** 系统管理员能完成周期配置、人员配置、归档操作，具备完整的系统运营能力。P1 全部完成后，系统管理员视角的主线功能基本闭环。

### 4.1 填报周期与锁定管理

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| 报告月配置 | 管理设置中设定当前报告月（YYYY-MM）；所有月度时间窗基于此计算 | `js/views/AdminSettings.js`、`server/index.js` |
| 锁定/解锁操作 | 手动锁定（提前）/ 解锁（开放填报）；`PATCH /api/admin/lock` | `js/views/AdminSettings.js`、`server/index.js` |
| 截止填报日期 | 到期后当前月所有未完成报告线自动置为「已完成」；管理设置提供手动触发按钮 | `js/views/AdminSettings.js`、`server/index.js` |
| 1-3 日财务核查提醒横幅 | 次月 1–3 日页面顶部显示横幅提示，不影响锁定状态 | `js/views/ProjectEditor.js` |

**最小验收：** 管理设置可更改报告月；手动锁定后主表进入只读模式（非管理员视角）；手动解锁后恢复可编辑；截止日期到达后报告线状态自动更新。

### 4.2 审批人员配置

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| 单表四列配置 | 板块 / 板块管理员 / 板块审批 / 项目群审批；`PATCH /api/admin/users` | `js/views/AdminSettings.js`、`server/index.js` |
| 平台用户下拉 | 下拉列表取自平台用户列表（原型可用 mock 数据） | `js/views/AdminSettings.js` |
| 自动跳过总监节点判断 | 后端在提交审批时判断板块管理员是否兼任板块审批，若是则跳过总监节点 | `server/index.js`、`server/sector-workflow.js` |

**最小验收：** 管理设置页可保存各板块审批人员；提交审批时自动跳过逻辑生效（配置兼任后流程直接进入群主审批）。

| 功能点 | 说明 | 相关文件 |

| 填报页表头自动刷新 | 保存后项目追踪表表头即时更新，无需重启 | `js/store.js`（`ensureFieldDictionary`）|

### 4.4 J 版归档与历史版本查看

## 5. P2 — 填报管理主链路（板块级）

**目标：** 打通"发起填报 → 板块管理员填报/保存 → 提交审批"这条主链。依赖 P0/P1 完成后进行。

| 通过操作 | 仅待办节点对应角色可见按钮；`POST /api/sectors/:code/approve` | `js/views/Approval.js` |
| 驳回操作 | 同权限；可选填驳回原因；退回草稿 + 解除板块锁定；`POST /api/sectors/:code/reject` | `js/views/Approval.js` |
| 驳回后退回 | 报告线状态回到「已退回」；板块管理员可重新编辑并再次提交 | `server/sector-workflow.js` |

**最小验收：** 总监进入审批页看到本板块只读表格和流程时间轴；待办节点显示通过/驳回按钮；通过后报告线状态推进；驳回后板块管理员可再次编辑提交。

### 6.2 审批状态流转

| 状态转换 | 触发操作 | 后端逻辑 |
|---|---|---|
| `draft` → `approve1` | 总监通过 | `approvalStatus = 'approve1'` |
| `draft` → `approve1`（跳过）| 板块管理员兼总监时自动跳过 | 提交审批时后端判断直接推进 |
| `approve1` → `approve2` | 群主通过 | `approvalStatus = 'approve2'`；报告线状态 → 「已完成」 |
| `approve1/approve2` → `draft` | 通过后任一审批角色驳回 | 退回草稿、解除板块锁定 |

**最小验收：** 完整走一次"提交 → 总监通过 → 群主通过"后，报告线状态为「已完成」；中途驳回后流程正确退回。

### 6.3 系统管理员审批纵览页

| 功能点 | 说明 | 相关文件 |
|---|---|---|
| 十二板块卡片 | 每卡展示板块名称、三步流程三态（提交填报/总监初审/群主复审）、状态标签 | `js/components/SystemAdminApprovalBoard.js` |
| 无审批操作 | 系统管理员审批页只读纵览，无通过/驳回按钮 | `js/components/SystemAdminApprovalBoard.js` |
| 与填报管理联动 | 各板块填报进度详情通过「填报管理」页查看，不在审批页重复展示 | — |

**最小验收：** 系统管理员审批页加载十二板块卡片；各板块审批状态正确反映（提交后卡片显示板块领导审批中）。

## 9. 里程碑与验收建议

| 里程碑 | 覆盖优先级 | 可验收标准 |
|---|---|---|
| **M1：数据底座可用** | P0 全部 | 系统管理员可查看/编辑/保存主表数据；系统字段刷新生效；初始化导入/重置可用；变更高亮基本可见 |
| **M2：系统运营闭环** | P0 + P1 | 系统管理员可完成一个完整月度周期：配置报告月 → 编辑数据 → 锁定 → 归档（J版）→ 解锁；审计日志可查；表头可配置 |
| **M3：填报管理主链路** | P0 + P1 + P2 | 板块管理员可通过填报管理发起报告线、填报保存、校验通过后提交审批；流转轨迹可查；快照生成正确 |
| **M4：审批闭环** | P0 + P1 + P2 + P3 | 总监/群主可在审批页通过或驳回；驳回后板块管理员可再次修改提交；审批完成后报告线状态为「已完成」 |
| **M5：PM 填报扩展** | P0–P4 | 项目经理可在报告线中填报本人项目、提交、导入导出；变更批注正确展示 |
| **M6：完整运营版** | P0–P5 | 预警抽屉可用；邮件提醒配置后可发送；Drawer 深度体验完整；经营管理只读视角可用 |
