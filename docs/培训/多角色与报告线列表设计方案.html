多角色与报告线列表设计方案

项目追踪表线上化 · 业务逻辑与功能设计

版本 v1.1 日期 2026-06-02 状态 草案讨论 Wood China

一、背景与问题

1.1 现状痛点

当前原型通过「角色切换」界面模拟不同角色的视图差异。正式环境中存在以下问题：

  • 用户无角色切换入口，但一个人可能同时拥有多个角色
  • 审批流只支持单条线展示，群主管理多个板块时无法并行查看
  • 所有项目在一张大表中展示，缺乏按板块/周期的组织维度

1.2 典型多角色场景

场景 角色组合 矛盾点
板块管理员兼项目经理 板块管理员 + 项目经理 是否需要以 PM 身份"提交"自己的项目？
群主兼项目经理 群主 + 项目经理 同一界面既要填报又要审批其他板块
板块管理员管多板块 板块管理员 × N 需要同时看到多个板块的审批状态
板块领导兼板块管理员 板块领导 + 板块管理员 自审自批的流程跳过问题

二、核心设计原则

2.1 权限向上合并

一个用户拥有多个角色时，取权限并集，高权限覆盖低权限：

权限层级

系统管理员 > 群主 > 板块领导 > 板块管理员 > 项目经理

  • 板块管理员 ∪ 项目经理 → 对自己的项目拥有板块管理员级别的编辑权限，无需单独"提交"
  • 群主 ∪ 项目经理 → 对自己的项目直接拥有填报+提交权限，对所辖板块项目拥有审批权限
  • 审批流中，当提交人本身是审批链上的某个节点时，该节点自动跳过

2.2 功能调整策略：最小变更原则

在当前系统基础上进行最小变更，不新增功能页面，仅调整现有功能的定位：

调整前（当前系统）：

  • 项目追踪表（编辑）
  • 审批流程（独立页）
  • 审计日志、表头配置、管理设置

调整后：

  • 项目追踪表 → 只读查看
  • 填报管理（新增，取代审批流程页，整合填报+提交+审批）
  • 审计日志、表头配置、管理设置：保持不变

以下表格列出典型角色组合下，用户在填报管理中的数据范围和操作权限：

角色组合 填报管理中的数据范围 可执行操作
项目经理
（单一角色）		 仅自己项目所属板块的报告线，含历史归档 填报自己项目、保存草稿、提交
板块管理员
（单板块）		 所辖板块全部报告线 查看所有PM填报进度、催办、提交审批
板块管理员 + 项目经理 所辖板块全部报告线（含自己项目） 自己项目无需PM提交环节，可直接编辑并提交审批
板块领导
（单板块）		 所辖板块全部报告线 查看汇总、审批、退回
板块领导 + 项目经理 所辖板块全部报告线 自己项目可直接编辑并提交，跳过板块管理员审批节点；同时可审批
群主
（管辖多板块）		 所辖多个板块的全部报告线，并行展示 查看多板块汇总、终审、退回
群主 + 项目经理 多板块报告线 + 自己项目报告线 自己项目跳过群主审批节点；可审批其他板块
系统管理员 全公司所有板块的全部报告线 全局查看、归档
关键设计要点
  • 填报管理统一入口：填报、提交、审批都在同一个功能中完成，通过列表→详情的方式组织
  • 项目追踪表保留但变为只读：提供全量数据的浏览、筛选和导出能力，不再承担编辑职责
  • 数据范围取并集：多角色用户看到的报告线是所有角色可见范围的并集
  • 审批跳过：当一个用户同时是提交者和审批者时，对应审批节点自动跳过，避免自审自批

2.3 Git-like 数据流模型

将数据的流转类比为 Git 版本管理，每一层只关心"收到了哪些变更，是否接受"：

Git 概念 系统对应 说明
main 分支 J 版（归档版） 上一周期最终确认的权威数据
fork/branch 开启新填报周期 各板块从 J 版中 fork 出本板块的数据副本
working copy PM 工作区 PM 在自己的项目范围内编辑
commit + push PM 提交 PM 将变更提交到板块报告线
code review 板块管理员审批 审查变更，可退回（reject）或通过（approve）
merge upstream 逐级汇总 板块→群组→全公司，层层合并
tag/release 新 J 版归档 最终确认后生成新的 J 版快照

3.2 列表视图（工作台首页）

所有角色进入系统后，首先看到的是报告线列表，根据角色不同，可见范围不同：

角色 可见报告线 列表展示重点
项目经理 自己项目所属板块的报告线（含历史归档） 我的填报状态、是否需要操作

  • 填报：点击进入详情页编辑数据（仅开放填报/已退回状态下可用）
  • 审批：点击进入详情页查看 diff 并执行通过/退回（仅当前审批节点对应角色可见）
  • 查看：点击进入详情页只读浏览数据
  • 导出：将当前报告线数据导出为 Excel

3.4 列表筛选与排序

  • 状态筛选：全部 / 需要我操作 / 进行中 / 已完成 / 已关闭
  • 板块筛选：按板块名称（多板块用户适用）
  • 周期筛选：按年月
  • 默认排序：需要操作的在前 → 进行中 → 已完成 / 已关闭（按时间倒序）

3.5 状态机与视角模型

3.5.1 报告线客观状态机

报告线采用统一客观状态机，状态本身不按角色拆分，但不同角色在列表中看到同一状态时，显示差异化的操作提示：

开放填报
→
审批中
(板块领导)
→
审批中
(群主)
→
已完成

↑ 已退回 ← 板块领导/群主退回   |   超期未完成 → 已关闭

状态 说明 触发条件
开放填报 板块管理员和 PM 可编辑的阶段 新周期开启时自动创建
审批中(板块领导) 板块领导审批阶段 板块管理员提交审批
审批中(群主) 群主终审阶段 板块领导审批通过
已退回 被退回至板块管理员，需重新编辑 板块领导或群主退回
已完成 当前报告线流程走完，数据合并至总表 群主审批通过
已关闭 当月填报期内未走完审批流程 超期未完成
关键规则
  • 报告线从「开放填报」到「审批中」的触发是板块管理员提交审批，而非 PM 提交
  • PM 提交仅表示 PM 将自己的数据提交给板块管理员，不改变报告线的客观状态
  • 「已退回」后回到「开放填报」，板块管理员和 PM 可重新编辑
  • 「已完成」表示单个报告线走完流程，数据合并到总表，不等于 J 版归档
  • 「已关闭」为终态，不可重新打开

3.5.2 PM 视角状态

PM 有独立的三状态视角，与报告线客观状态解耦：

开放填报
→
已提交
→
已关闭

已提交 = 等待板块管理员处理   |   已关闭 = 板块管理员已提交审批，PM 未提交则自动关闭

PM 视角状态 说明 对应的报告线客观状态
开放填报 PM 可以编辑自己的项目 开放填报
已提交 PM 已将数据提交给板块管理员 开放填报 / 审批中(板块领导) / 审批中(群主)
已关闭 PM 填报入口已关闭，无法再编辑 审批中(板块领导) / 审批中(群主) / 已关闭
「已关闭」触发条件
  • 当板块管理员提交审批时，所有未提交的 PM 状态自动变为「已关闭」
  • PM 在「已关闭」状态下只能查看自己的项目数据（只读），无法编辑

注意：「已提交」只是 PM 的视角状态，不是报告线的客观状态。PM 提交后，报告线仍处于「开放填报」，直到板块管理员提交审批才进入「审批中」。

四、报告线详情

4.1 进入逻辑

点击列表中的报告线进入详情页，详情页内容根据用户角色和报告线状态动态展示：

用户角色 报告线状态 详情页行为
项目经理 开放填报 只显示自己负责的项目，可编辑
审批中(板块领导) / 审批中(群主) 只显示自己的项目，只读
已退回 只显示自己的项目，可重新编辑
已关闭 只显示自己的项目，只读（填报入口已关闭）
板块管理员 开放填报 显示板块所有项目，可催办/查看进度
审批中(板块领导) 显示板块所有项目 + 变更 diff，等待板块领导审批
板块总监 审批中(板块领导) 显示板块汇总 + 变更 diff，可批准/退回
群主 审批中(群主) 显示板块汇总 + 变更 diff，可批准/退回

4.3 PM 视角的特殊说明

  • PM 点入报告线后，只能看到和编辑自己负责的项目
  • 历史已完成的报告线也出现在列表中，PM 可点入查看自己项目的历史数据（只读）
  • 如果 PM 只有一条当前需要操作的报告线，列表仍正常显示（因历史记录也在列表中）

五、Git-like 数据流详细设计

5.1 周期开启（Fork）

系统管理员操作

点击「开启新周期 2026年6月」→ 系统为 12 个板块分别创建报告线，每条报告线从最新 J 版快照中 fork 出该板块的项目数据作为 baseline。

5.2 填报与提交（Commit & Push）

  • 保存草稿 = local commit：不影响他人，PM 可随时保存
  • 提交 = push to 板块报告线：系统记录哪些字段相对 baseline 发生了变更（diff）

5.3 审批与合并（Review & Merge）

审批层级 操作 说明
板块管理员 编辑/汇总 / 提交审批 板块管理员可直接编辑板块数据（PM 填报非必须），确认后提交审批
板块总监 查看 diff / 退回到板块管理员 / 通过 板块管理员提交审批后的汇总变更
群主 查看 diff / 退回到板块管理员 / 通过 板块总监确认后的最终变更

5.4 归档（Merge to Main / Tag）

系统管理员操作

确认归档 → 所有板块报告线汇总生成新 J 版快照 → 新 J 版成为下一周期的 main 分支 → 所有报告线状态更新为「已完成」

7.3 审批流自动跳过

当用户同时拥有提交者和审批者角色时，审批节点自动跳过：

九、开放问题（已确认）

编号 问题 结论
Q1 板块管理员是否可以代替 PM 填报？ ✅ 可以。板块管理员可统一填报而不需要 PM 参与，但 PM 仍保留填报入口。PM 填报不是必须的前置条件。
Q2 退回粒度？ ✅ 退回到板块管理员。审批退回统一退回到板块管理员层级，不细分到单个 PM。
Q3 多 PM 提交时序？ ✅ 不强制等待。PM 填报不是必须的，板块管理员随时可以提交审批，无需等待所有 PM 填报完成。
Q4 历史报告线如何展示？ ✅ 不折叠。历史报告线按时间倒序排在列表最后，不做折叠处理。
