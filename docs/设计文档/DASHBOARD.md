
# 数据看板（Dashboard）产品文档的设计注意事项清单
目标是：

- 你在画原型和写 PRD 时可以快速对齐细节
- 开发在实现时不需要反复追问“格式、单位、口径、交互”

以下规范建立在格式塔原理和尼尔森十大交互原则基础上：

## 1. 展示层规范（数字、单位、格式）

- **千分符**：所有“计数类 / 金额类 / 大数字”默认启用千分位分隔（如 12,345）。
- **小数位规则**（必须写死，不要靠感觉）：
    - 金额：始终保留 **2 位小数**（例：3,871.01）。
    - 比例/百分比：默认保留 **2 位小数**（例：94.15%）。如空间不足可降到 1 位，但同一模块必须一致。
    - 人天/工时：建议保留 **2 位小数** 或按业务约定（例如工时可 1 位），同一指标在所有页面一致。
    - 计数：例如待办数量、人数等，保留**整数**。
- **负数与符号**：
    - 明确是否允许负数（如同比/环比可能为负）。
    - 负数展示规则：`-1,234.56` 。
- **单位必须显式**：
    - 每个指标都要在标题或数值旁显示单位（例：万元、亿元、个、%）。
    - 单位优先放在指标标题旁，而不是数值旁，例如：`年度完成合同额（万元）`。
    - 同一行/同一区域的指标单位必须一致，便于用户跨卡片比较，降低认知负荷。
- **缩写规则**：明确是否允许使用 `K/M/B` 或 `万/亿` 进行缩写。
    - 如果启用缩写，必须写清楚进位（例如 1.2 亿 = 120,000,000）。
    - 建议：财务看板优先使用“万/亿”，并在卡片标题统一标注。

## 2. 口径与数据来源

- **每个指标必须写口径**（建议在指标“信息 i”里展示）：
    - 业务定义：这个数是什么。
    - 计算逻辑：包含以下几类
        - 排除项
        - 过滤条件
        - 时间范围
        - …
    - 数据来源：表/接口/服务名，或至少写“来自 XX 系统”。
    - 更新时间：T+0 / T+1 / 每小时 / 每日几点/每周几/每月几日。
- **时间口径**：
    - “本月/本年/截至今日”必须明确起止：是否按自然月，是否按财年，是否包含当天。
    - “昨日/上月累计”等必须明确是否按数据刷新时间切。
- **重复口径的复用**：同一口径在多个指标复用时，建立“口径编号/名称”，避免散落在各处写不同版本。

## 3. 交互与下探（Drill down）

- **是否需要下探**要在 PRD 中明确为：
    - 不下探：卡片仅展示数值。
    - 下探到列表：点击卡片进入明细表（带筛选条件默认继承）。
    - 下探到维度分析：例如从“全公司”下钻到“事业部/部门/项目”。
- **下探继承规则**：
    - 筛选项继承：组织、时间、项目、币种/单位等是否继承。
    - 指标口径继承：下探层级必须保持同一口径，除非明确写“下探口径不同”。
- **点击区域**：明确是“整张卡片可点”还是“仅箭头/图标可点”，并给出 hover 提示。

## 4. 数据看板布局与信息层级（内容区）

- **若涉及到看板的设计，信息分层建议**（从上到下）
    - 顶部：核心 KPI 卡片（少而关键，4–6 个）。
    - 其余区域：分析模块（构成、趋势、对比、达成率、明细表、交叉表，该类型的模块布局一般情况下，不超过**3列**）。
- **同一卡片中可比**：单位、保留小数位、颜色语义一致。
- **空间不足时优先级**：数值 > 单位 > 辅助信息（同比/环比/说明）。不要把核心数挤到看不清。
- **每个卡片设置Tooltip提示**

## 5. 趋势、对比与颜色语义

- **同比/环比的方向**：
    - 明确“上升是好还是坏”（例如成本上升可能是坏）。
    - 不要硬编码“红涨绿跌”，而是按指标类型配置：
        - 正向指标：上升=好
        - 负向指标：上升=坏
- **颜色与符号**：
    - 建议用“箭头 + 颜色”双编码，避免仅靠颜色（色弱问题）。
    - 写清楚阈值：例如变化小于 0.1% 是否显示。

## 6. 筛选器与默认值（时间、组织、维度）

- **全局筛选器清单**：
    - 时间：年/月/日期范围
        - 如果有多种时间口径的（例如发起日期、确认日期等），需要确定是哪一口径
    - 组织：需要明确是以下的哪个范围
        - 所有板块/所有项目执行部门/所有项目归属
        - **⚠️ 着重强调**：不要出现已被取消的历史部门（除特殊原因外）
    - 项目：项目/合同/客户
- **默认值**：必须写清楚默认选中什么（例如默认当年、默认全公司）。
- **筛选对哪些组件生效**：如果有模块不受全局筛选影响，要在 UI 上标识。

## 7. 图表（ECharts：饼图/柱状图/折线图）设计规范

- **统一约束（所有图表通用）**
    - **图表类型选择要可解释**：
        - 饼图：构成占比，分类不超过 **6** 个；超过则用条形图或“Top N + 其他”。
        - 柱状图：分类对比（离散维度），适合 TopN。
        - 折线图：时间序列趋势（连续维度），不用于离散类别对比。
    - **数值格式**：沿用本页第 1 章规则（千分符、金额 2 位小数、百分比 2 位小数、空值为 `—`）。
    - **坐标轴（xAxis / yAxis）**
        - **轴标题与单位**：
            - Y 轴必须可推导出单位：优先 `yAxis.name` 写单位（例：`金额（万元）`），或在 tooltip/卡片标题显式标注。
            - 无特殊要求，**不要使用双轴**展示多个单位不一致或值域跨度相差大的多个指标
        - **轴刻度与数值格式**（`axisLabel.formatter`）：
            - 轴刻度同样需要千分符与小数位一致。
            - 金额轴建议避免过密小数，保持 0/2 位策略一致。
        - **刻度范围与基线**：
            - 是否强制从 0 开始必须写清楚（对比类柱状图通常从 0；含正负值或波动较小的折线图可不从 0）。
            - 需要阈值/目标线时，用 `markLine` 或额外 series 明确。
        - **类目轴标签（长文本）**：
            - 允许截断显示（`axisLabel.overflow = 'truncate'` 或 formatter 截断），但 tooltip 必须能看到全称。
            - 类目过多时：优先横向条形图或启用 dataZoom。
    - **数据标签（label）**
        - **默认策略**：除非业务要求“直接读数”，否则默认关闭，避免遮挡。
        - **开启场景**：
            - TopN 排名柱状图（显示数值）。
            - 单序列折线图关键点（只标注最大/最小/最新点）。
            - 饼图仅标注 TopN，其余走 legend/tooltip。
        - **格式**：label 与 tooltip 使用同一格式化规则（千分符、2 位小数、百分比 2 位）。
        - **位置**：柱状图 label 建议 `position: 'top'`（或条形图用 `right'`）；饼图 label 建议避免环外拥挤。
        - ⚠️ **着重强调：**检查各场景下数据标签（尤其饼图）是否越界；若越界，调整绘图区域/图表尺寸/padding或标签位置。
    - **颜色规范**（ECharts `color` / `series.itemStyle.color`）：
        - 同一业务维度（如部门、板块）的颜色映射，在同一界面上必须一致。
        - 使用调色板固定顺序，不允许每次随机配色。
        - 颜色同时承担“好/坏”语义时，必须与第 5 章一致（正向/负向指标配置化），并用图例或 tooltip 明示。
    - **网格与布局（grid）**：
        - 必须保证轴名称、刻度、legend 不被裁切（常见问题是 `grid.containLabel`）。
        - 图表与卡片边缘留白一致，避免贴边。
    - **图例（legend）**：
        - 默认显示在顶部或底部，不遮挡图形。
        - 图例项过多时允许滚动（`legend.type = 'scroll'`）。
    - **Tooltip（必须）**：
        - 必须包含：指标名、数值、单位
        - 可选：维度名、时间（若有）
        - 建议使用 `trigger: 'axis'`（折线/柱状）以便对齐同一 X 点多序列对比；饼图用 `trigger: 'item'`。
    - **空值/断点**：
        - 折线图遇到空值是否断开必须写清楚（ECharts 可通过 `connectNulls` 决定）。
        - 0 与 null 必须区分（0 表示确实为零，null 表示无数据）。
    - **交互（按需启用，并写进 PRD）**：
        - hover 高亮：默认开启（`emphasis`）。
        - 点击下探：通过 `series` 的 click 事件实现，需明确下探目标与筛选继承规则（见第 3 章）。
            - 若无特殊要求，尽量不使用图表的下探功能。
        - 缩放：时间序列较长时启用 dataZoom（`dataZoom`），并约定默认显示窗口（如最近 12 个月）。
- **饼图（Pie）**
    - 适用：占比构成；不用于趋势。
    - 关键配置建议：
        - `series.type = 'pie'`；`radius` 建议用环形（如 `['45%','65%']`）增强可读性。
        - 标签（label）默认不在图上堆满：
            - 仅展示 TopN 标签，其余在 legend/tooltip 展示。
            - 百分比建议由 ECharts `params.percent` 展示，并统一保留 2 位。
        - 分类过多：合并为“其他”，并在 tooltip/下钻中可展开明细。
- **柱状图（Bar）**
    - 适用：类别对比、TopN 排名。
    - 关键配置建议：
        - `series.type = 'bar'`；TopN 建议按数值排序。
        - 类别名很长：
            - 优先用横向条形图（`bar` + 类别在 yAxis）。
            - 或对 xAxis label 做截断并在 tooltip 显示全称（`axisLabel.formatter`）。
        - 多序列对比：使用分组柱；若强调累计构成，使用堆叠（`stack`），并明确 stack 口径。
        - 需要目标/阈值：用 `markLine` 或 `visualMap` 标识阈值，并写清楚阈值来源。
- **折线图（Line）**
    - 适用：时间序列趋势、对比多条趋势线。
    - 关键配置建议：
        - `series.type = 'line'`；`smooth` 是否开启需写清楚（趋势看板建议默认关闭，避免误读拐点）。
        - 点位（symbol）：数据点少时显示，数据点多时可隐藏以提升性能（`showSymbol: false`）。
        - 面积（areaStyle）：仅在强调“区间量级”时使用，并避免多条线同时铺满导致难以阅读。
        - 时间粒度：月/周/日必须明确；xAxis 为 time 或 category 要一致，并说明缺失日期如何处理。
- **开发交付（图表必须提供的字段清单）**
    - 图表类型（pie/bar/line）与用途说明。
    - 维度字段（xAxis / legend 维度）与排序规则。
    - 指标字段（series）列表：单位、格式、小数位、正负向语义。
    - tooltip 内容模板（需要展示哪些字段）。
    - 交互开关：legend 是否可滚动、是否 dataZoom、是否 click 下钻。

## 8. 表格（交叉表/明细表）需要明确的能力

- **排序：**哪些列可排序。
- **固定列：**是否固定首列（名称列）。
- **分页：**页大小默认值。
- **汇总：**是否展示合计/小计，合计口径是什么。
- **复制/导出：**是否需要导出 Excel。

## 9. 异常与空值处理（最容易扯皮的点）

- **无数据**：显示 `—`，不要显示 0（除非业务明确 0 的含义）。
- **除零/无定义**：显示 `—`，并在 tooltip 提示原因。
- **加载态**：骨架屏或占位符。
- **权限/范围不足**：提示“无权限/无数据范围”，避免看起来像系统加载问题。

## 10. 性能与刷新策略（让体验稳定）

- 指标刷新频率：实时/分钟级/小时级/日级。
- 大表/交叉表：明确是否按需加载、是否限制最大行数。
- 缓存策略：是否允许缓存（例如 5 分钟）。

## 11. 文档交付给开发的最小集合（建议模板）

- 页面结构：模块清单 + 组件位置
- 每个模块：
    - 指标列表（标题、单位、格式、小数位、颜色语义）
    - 口径说明（含过滤条件、数据来源、刷新频率）
    - 交互说明（下探、跳转、hover、点击区域）
    - 异常处理（空值、无权限、加载态）
