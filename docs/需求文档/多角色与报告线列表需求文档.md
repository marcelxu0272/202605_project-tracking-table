# 多角色与报告线列表需求文档

> **版本：** v1.0  
> **日期：** 2026-06-01  
> **状态：** 草案讨论

---

## 1. 背景与问题

### 1.1 现状

当前原型通过「角色切换」界面模拟不同角色的视图差异，正式环境中：

- 用户无角色切换入口，但一个人可能同时拥有多个角色
- 审批流只支持单条线展示，群主管理多个板块时无法并行查看
- 所有项目在一张 Luckysheet 大表中展示，缺乏按板块/周期的组织维度

### 1.2 典型多角色场景

| 场景 | 角色组合 | 矛盾点 |
|---|---|---|
| 板块管理员兼项目经理 | sector_admin + project_manager | 是否需要以 PM 身份"提交"自己的项目？ |
| 群主兼项目经理 | group_leader + project_manager | 同一界面既要填报又要审批其他板块 |
| 板块管理员管多板块 | sector_admin × N | 需要同时看到多个板块的审批状态 |
| 板块领导兼板块管理员 | sector_director + sector_admin | 自审自批的流程跳过问题 |

## 2. 核心设计原则

### 2.1 权限向上合并

一个用户拥有多个角色时，取**权限并集**，高权限覆盖低权限：

```
system_admin > group_leader > sector_director > sector_admin > project_manager
```

**规则：**
- 板块管理员 ∪ 项目经理 → 对自己的项目拥有板块管理员级别的编辑权限，无需以 PM 身份单独"提交"
- 群主 ∪ 项目经理 → 对自己的项目直接拥有填报+提交权限，对所辖板块项目拥有审批权限
- 审批流中，当提交人本身是审批链上的某个节点时，该节点**自动跳过**

#### 2.2 功能调整策略：最小变更原则

在当前系统基础上进行**最小变更**，不新增功能页面，仅调整现有功能的定位：

**调整前（当前系统）：**
- 项目追踪表（`/editor`）：PM 和板块管理员填报编辑
- 审批流程（`/approval`）：总监和群主审批
- 审计日志、表头配置、管理设置：系统管理员专属

**调整后：**
- 项目追踪表（`/editor`）→ **只读查看**（全量数据浏览、导出）
- **报告线管理（`/report-lines`）**→ **新增**，取代原审批流程页，整合填报+提交+审批
- 审计日志、表头配置、管理设置：保持不变

以下表格列出典型角色组合下，用户在**报告线管理**中的数据范围和操作权限：

| 角色组合 | 报告线管理中的数据范围 | 可执行操作 |
|---|---|---|
| **项目经理**（单一角色） | 仅自己项目所属板块的报告线，含历史归档 | 填报自己项目、保存草稿、提交 |
| **板块管理员**（单板块） | 所辖板块全部报告线 | 查看所有PM填报进度、催办、提交审批 |
| **板块管理员** + **项目经理** | 所辖板块全部报告线（含自己项目） | 自己项目无需PM提交环节，可直接编辑并提交审批 |
| **板块领导**（单板块） | 所辖板块全部报告线 | 查看汇总、审批、退回 |
| **板块领导** + **项目经理** | 所辖板块全部报告线 | 自己项目可直接编辑并提交，跳过板块管理员审批节点；同时可审批 |
| **群主**（管辖多板块） | 所辖多个板块的全部报告线，并行展示 | 查看多板块汇总、终审、退回 |
| **群主** + **项目经理** | 多板块报告线 + 自己项目报告线 | 自己项目跳过群主审批节点；可审批其他板块 |
| **系统管理员** | 全公司所有板块的全部报告线 | 全局查看、归档 |

**关键设计要点：**
- **报告线管理统一入口：** 填报、提交、审批都在同一个功能中完成，通过列表→详情的方式组织
- **项目追踪表保留但变为只读：** 提供全量数据的浏览、筛选和导出能力，不再承担编辑职责
- **数据范围取并集：** 多角色用户看到的报告线是所有角色可见范围的并集
- **审批跳过：** 当一个用户同时是提交者和审批者时，对应审批节点自动跳过，避免自审自批

### 2.3 Git-like 数据流模型

将数据的流转类比为 Git 版本管理：

| Git 概念 | 系统对应 | 说明 |
|---|---|---|
| main 分支 | J 版（归档版） | 上一周期最终确认的权威数据 |
| fork/branch | 开启新填报周期 | 各板块从 J 版中 fork 出本板块的数据副本 |
| working copy | PM 工作区 | PM 在自己的项目范围内编辑 |
| commit + push | PM 提交 | PM 将变更提交到板块报告线 |
| code review | 板块管理员审批 | 审查变更，可退回（reject）或通过（approve） |
| merge upstream | 逐级汇总 | 板块→群组→全公司，层层合并 |
| tag/release | 新 J 版归档 | 最终确认后生成新的 J 版快照 |

**核心优势：**
- 每一层只关心"收到了哪些变更，是否接受"
- 退回 = reject，重新填报 = 修改后再次提交
- 数据隔离天然——每个板块、每个 PM 只操作自己 fork 出来的数据
- 冲突处理明确——如果同一字段被多人修改，逐级审批时由审批人决定

## 3. 报告线列表设计

### 3.1 概念定义

**报告线（Report Line）**：以「板块 × 月度周期」为单位的工作项，是填报、审批、归档的最小管理粒度。

每条报告线包含：
- 所属板块
- 所属周期（年月）
- 当前状态（待填报 / 填报中 / 已提交 / 审批中 / 已通过 / 已退回 / 已归档）
- 包含的项目数量
- 当前审批节点
- 最后更新时间

### 3.2 列表视图（报告线管理首页）

所有角色进入系统后，首先看到的是**报告线列表**，根据角色不同，可见范围不同：

| 角色 | 可见报告线 | 列表展示重点 |
|---|---|---|
| 项目经理 | 自己项目所属板块的报告线（含历史归档） | 我的填报状态、是否需要操作 |
| 板块管理员 | 所辖板块的所有报告线 | 板块整体进度、待审批数 |
| 板块领导 | 所辖板块的所有报告线 | 待我审批的报告线 |
| 群主 | 所辖多个板块的所有报告线 | 多板块并行状态一览 |
| 系统管理员 | 全部报告线 | 全局进度监控 |

### 3.4 列表筛选与排序

- **状态筛选：** 全部 / 需要我操作 / 进行中 / 已归档
- **板块筛选：** 按板块名称（多板块用户适用）
- **周期筛选：** 按年月
- **默认排序：** 需要操作的在前 → 进行中 → 已归档（按时间倒序）

## 4. 报告线详情（点入后）

### 4.1 进入逻辑

点击列表中的报告线进入详情页，详情页内容根据用户角色和报告线状态动态展示：

| 用户角色 | 报告线状态 | 详情页行为 |
|---|---|---|
| 项目经理 | 待填报/填报中 | 只显示自己负责的项目，可编辑 |
| 项目经理 | 已提交/审批中 | 只显示自己的项目，只读 |
| 项目经理 | 已退回 | 只显示自己的项目，可重新编辑 |
| 板块管理员 | 填报中 | 显示板块所有项目，可催办/查看进度 |
| 板块管理员 | 待审批（初审） | 显示板块所有项目 + 变更 diff，可批准/退回 |
| 板块领导 | 待审批（复审） | 显示板块汇总 + 变更 diff，可批准/退回 |
| 群主 | 待审批（终审） | 显示板块汇总 + 变更 diff，可批准/退回 |

### 4.3 PM 视角的特殊说明

- PM 点入报告线后，**只能看到和编辑自己负责的项目**（与原先 Luckysheet 中的行级权限逻辑一致）
- 历史已归档的报告线也出现在列表中，PM 可点入查看自己项目的历史数据（只读）
- 如果 PM 只有一条当前需要操作的报告线，列表仍正常显示（因历史记录也在列表中）

## 5. Git-like 数据流详细设计

### 5.1 周期开启（Fork）

```
系统管理员 点击「开启新周期 2026年6月」
    │
    ├── 板块A 报告线创建 ← fork(J版, 板块A的项目集)
    ├── 板块B 报告线创建 ← fork(J版, 板块B的项目集)
    ├── 板块C 报告线创建 ← fork(J版, 板块C的项目集)
    └── ...（十二板块）
```

**Fork 的数据内容：**
- 从最新 J 版快照中提取该板块所属的项目数据
- 作为本周期的 baseline（基线）
- PM 的编辑基于此 baseline 进行

### 5.2 填报与提交（Commit & Push）

```
PM 编辑自己的项目数据（working copy）
    │
    ├── 保存草稿 = local commit（不影响他人）
    │
    └── 提交 = push to 板块报告线
         │
         └── 系统记录: 哪些字段相对 baseline 发生了变更（diff）
```

### 5.3 审批与合并（Review & Merge）

```
板块管理员 编辑/汇总板块项目数据（PM 可填报但非必须）
    │
    ├── 查看 diff（相对 baseline 的变更汇总）
    │
    └── 提交审批 → 板块领导
         │
         板块领导审批
         │
         ├── 退回 → 退回到板块管理员
         │
         └── 通过 → 提交给群主
              │
              群主终审
              │
              ├── 退回 → 退回到板块管理员
              │
              └── 通过 → 标记为待归档
```

### 5.4 归档（Merge to Main / Tag）

```
系统管理员 确认归档
    │
    ├── 所有板块报告线汇总 → 生成新 J 版快照
    ├── 新 J 版成为下一周期的 main 分支
    └── 所有报告线状态更新为「已归档」
```

### 5.5 变更追踪（Diff）

每一级审批时，系统展示的 diff 内容：

| 审批层级 | Diff 基线 | Diff 内容 |
|---|---|---|
| 板块管理员 | fork 时的 baseline | 各 PM 修改了哪些字段 |
| 板块领导 | 同上 | 板块管理员确认后的汇总变更 |
| 群主 | 同上 | 板块领导确认后的最终变更 |

## 7. 权限矩阵

### 7.1 功能权限

| 功能 | PM | 板块管理员 | 板块领导 | 群主 | 系统管理员 |
|---|---|---|---|---|---|
| 查看报告线列表 | ✅ 自己板块 | ✅ 所辖板块 | ✅ 所辖板块 | ✅ 所辖板块 | ✅ 全部 |
| 填报项目数据 | ✅ 自己项目 | ✅ 板块全部 | ❌ | ❌ | ✅ 全部 |
| 提交审批（板块管理员发起） | ❌ | ✅ | ❌ | ❌ | ❌ |
| 审批 | ❌ | ❌ | ✅ | ✅ | ❌ |
| 退回 | ❌ | ❌ | ✅ | ✅ | ❌ |
| 归档 | ❌ | ❌ | ❌ | ❌ | ✅ |
| 系统管理 | ❌ | ❌ | ❌ | ❌ | ✅ |

### 7.2 多角色合并规则

```javascript
// 伪代码：计算用户有效权限
function resolvePermissions(user) {
  const roles = user.roles; // e.g. ['sector_admin', 'project_manager']
  
  // 取所有角色权限的并集
  const permissions = roles.reduce((acc, role) => {
    return union(acc, ROLE_PERMISSIONS[role]);
  }, {});
  
  // 数据范围取并集
  const dataScope = {
    sectors: union(...roles.map(r => getSectorScope(user, r))),
    projects: union(...roles.map(r => getProjectScope(user, r))),
  };
  
  return { permissions, dataScope };
}
```

### 7.3 审批流自动跳过

当用户同时拥有提交者和审批者角色时，审批节点自动跳过：

| 场景 | 行为 |
|---|---|
| 板块管理员提交自己的项目 | 板块管理员直接提交审批，跳过 PM 提交环节 |
| 板块总监兼板块管理员 | 跳过板块总监审批节点，直接进入群主审批 |
| 群主兼板块管理员 | 跳过群主审批节点，仅需板块总监审批（若也兼任则直接归档） |

## 8. 与现有系统的关系

### 8.1 保留的能力

| 能力 | 说明 |
|---|---|
| Luckysheet 表格编辑 | 报告线详情内仍使用 Luckysheet 展示项目数据 |
| 字段权限矩阵 | 行级（PM只见自己项目）+ 字段级（角色×锁定期）保持不变 |
| 公式引擎 | auto_calc 字段逻辑不变 |
| 快照机制 | I/D/J 版快照继续使用，报告线 fork 基于 J 版快照 |
| 预警系统 | 保持不变，继续以 AlertsDrawer 组件形式存在 |
| 变更追踪 | 与 Git-like diff 机制整合，审批时展示字段级变更 |

### 8.2 需要调整的部分

| 模块 | 调整内容 |
|---|---|
| 路由系统 | 新增 `/#/report-lines` 和 `/#/report-lines/:id`；`/#/editor` 改为只读 |
| 登录跳转 | 所有角色统一跳转报告线管理，不再按角色跳不同首页 |
| Store 数据结构 | 新增报告线列表状态、当前报告线上下文 |
