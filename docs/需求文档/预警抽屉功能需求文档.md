## 1. 功能概述

### 1.1 场景描述

系统管理员专属的全公司维度预警汇总面板，聚合所有项目的活跃预警，便于快速定位风险项目并督促责任人消除。

### 1.2 用户故事

> 作为**系统管理员**，我希望在项目追踪表页面打开一个抽屉，一次性查看**所有项目**的预警状态，并通过搜索、筛选快速定位目标项目；对于已确认无需处理的预警，我希望能**手动永久忽略**，避免重复出现干扰判断。

### 1.3 约束边界

- **权限**：仅 `system_admin` 角色可见，非快照查看模式
- **入口**：仅项目追踪表页工具栏
- **数据范围**：当前系统年份 + 当前报告月（可通过 query 参数切换）
- **计算方式**：每次打开抽屉时实时计算，不缓存

## 2. 预警类型定义

与项目详情 Drawer 预警区一致，共四类：

| 预警类型 | 标识符 | 标签颜色 | 触发条件 |
|---|---|---|---|
| 存量开票额为负 | `invoice_stock_negative` | 红色（danger） | R 列（开票额 − 合同额）< 0 |
| 存量合同额为负 | `contract_stock_negative` | 红色（danger） | S 列（合同额 − 完成额）< 0 |
| 有完成额无工时 | `completion_no_hours` | 橙色（warning） | 当月有完成额但工时 < 0.05h |
| 有工时无完成额 | `hours_no_completion` | 橙色（warning） | 当月有工时但完成额 < 0.005 万 |

阈值规则：金额 < 0.005 视为 0；工时 < 0.05h 视为无工时。

## 3. 入口与交互

### 3.1 工具栏按钮

- **位置**：项目追踪表页工具栏，"刷新数据"按钮左侧
- **图标**：铃铛（`el-icon-bell`）
- **文案**：「项目预警」
- **可见性**：`canShowAlertsButton = isSystemAdmin && !isViewingSnapshot`

### 3.2 抽屉行为

- 点击按钮 → 抽屉从右侧滑出（800px 宽），同时触发后端计算
- 关闭抽屉 → 清空本地数据
- 每次打开均重新计算

### 3.3 卡片交互

| 卡片状态 | 点击行为 |
|---|---|
| 活跃（active） | 关闭预警抽屉 → 打开对应项目详情 Drawer |
| 已消除（resolved） | 无响应 |
| 已忽略（dismissed） | 无响应 |

## 4. 抽屉 UI 设计

### 4.1 头部

- 标题：「项目预警总览」
- 统计摘要：「共 N 条预警（活跃 M 条），涉及 K 个项目」

### 4.2 卡片信息

每条预警以卡片形式展示：

| 信息项 | 说明 |
|---|---|
| 预警类型标签 | 彩色标签（红/橙）+ 图标 |
| 板块代码与名称 | 卡片右上角 |
| 项目编号 | 加粗显示 |
| 项目名称 | 项目号右侧 |
| 预警详情 | 具体数值描述（如「R列(存量开票额) = -12.34万」） |
| 首次检测时间 | 卡片底部左侧 |
| 操作区 | 卡片底部右侧（见 §4.4） |

### 4.3 筛选与搜索

| 功能 | 控件 | 说明 |
|---|---|---|
| 关键词搜索 | 输入框 | 模糊匹配项目号、名称、预警类型、详情 |
| 预警类型 | 下拉多选 | 按四类预警过滤 |
| 项目板块 | 下拉单选 | 自动从当前数据中提取板块列表（去重） |
| 状态 | 下拉单选 | 活跃（默认）/ 已消除 / 已忽略 / 全部 |
| 重置 | 按钮 | 清空全部筛选，恢复默认状态（活跃） |

### 4.4 操作区

| 状态 | 显示内容 |
|---|---|
| active | 「忽略」按钮 + 「点击查看项目详情 →」 |
| resolved | 「已消除」灰色文字 |
| dismissed | 「已忽略（永久）」斜体灰色文字 |

### 4.5 统计栏

显示当前活跃预警按类型统计的计数，便于快速了解风险分布：

```
⚠ 存量开票额为负: 1   ⚠ 存量合同额为负: 1   ⏰ 有完成额无工时: 1   ⏰ 有工时无完成额: 1
```

### 4.6 分页

- 默认每页 20 条，可切换 10 / 20 / 50 / 100
- 显示当前页码与筛选后总数
- 仅在总数超过 pageSize 时显示分页控件

### 4.7 空状态

- 无预警记录：图标 + 「暂无预警记录」
- 无匹配结果：图标 + 「无匹配结果，请调整筛选条件」

## 5. 预警状态管理

### 5.1 三种状态

| 状态 | 标识符 | 含义 | 触发方式 |
|---|---|---|---|
| 活跃 | `active` | 预警条件当前满足 | 系统自动计算 |
| 已消除 | `resolved` | 预警条件已不满足 | 系统自动标记（下次计算时不再出现） |
| 已忽略 | `dismissed` | 管理员手动永久消除 | 管理员手动操作 |

### 5.2 状态流转

```
              ┌──────────┐
 (条件出现)──►│  active  │──(条件消失)──►┌──────────┐
              └────┬─────┘              │ resolved │
                   │                    └──────────┘
            (手动忽略)                       ▲
                   │                    (条件重新出现
                   ▼                     时重新激活)
              ┌───────────┐
              │ dismissed │  ← 永久，不再出现
              └───────────┘
```

### 5.3 持久化规则

- 所有预警均持久化存储至数据库
- UNIQUE 约束：`(project_no, alert_type, year, month_idx)` 确保同项目同类型同月不重复
- 每次打开抽屉时系统重新计算：
  - 新出现的预警 → 写入 `active`
  - 已存在的活跃预警 → 更新 `lastSeenAt`
  - 不再出现的活跃预警 → 标记 `resolved`，记录 `resolvedAt`
- 已消除的预警如果条件重新出现，会自动重新激活（`firstDetectedAt` 重置）

## 6. 手动永久忽略

### 6.1 操作入口

每张活跃预警卡片右下角的「忽略」按钮（`el-button size=mini type=info plain`）。

### 6.2 确认对话框

点击「忽略」后弹出确认对话框：

- **标题**：永久忽略预警
- **内容**：「确定要永久忽略此预警吗？忽略后，该项目的此类预警将不再出现在任何月份的预警列表中。此操作不可撤销。」
- **确认按钮**：确认忽略
- **取消按钮**：取消

### 6.3 永久忽略行为

- 确认后调用 `POST /api/admin/alerts/:id/dismiss`
- 后端将 `(project_no, alert_type)` 写入独立的 `project_alert_dismissals` 表
- 当前月份的预警行状态更新为 `dismissed`
- 后续月份的计算中，已忽略的 `(project_no, alert_type)` 组合不会出现在活跃列表中
- **跨月生效**：即使切换到其他月份，已忽略的预警也不会出现
- **不可撤销**：当前版本不支持撤销操作（数据库层面支持，UI 不暴露）

### 6.4 幂等性

重复忽略同一预警不会报错（`INSERT OR IGNORE` 策略）。

## 7. 后端技术方案

### 7.1 数据表

#### project_alerts（预警记录表）

```sql
CREATE TABLE project_alerts (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    project_no        TEXT NOT NULL,
    project_name      TEXT NOT NULL DEFAULT '',
    sector_code       TEXT NOT NULL DEFAULT '',
    sector_name       TEXT NOT NULL DEFAULT '',
    alert_type        TEXT NOT NULL,
    alert_label       TEXT NOT NULL DEFAULT '',
    detail            TEXT NOT NULL DEFAULT '',
    year              INTEGER NOT NULL,
    month_idx         INTEGER NOT NULL,
    status            TEXT NOT NULL DEFAULT 'active',  -- active | resolved | dismissed
    first_detected_at TEXT NOT NULL DEFAULT '',
    resolved_at       TEXT NOT NULL DEFAULT '',
    last_seen_at      TEXT NOT NULL DEFAULT '',
    UNIQUE(project_no, alert_type, year, month_idx)
);
```

#### project_alert_dismissals（永久忽略记录表）

```sql
CREATE TABLE project_alert_dismissals (
    project_no   TEXT NOT NULL,
    alert_type   TEXT NOT NULL,
    dismissed_at TEXT NOT NULL,
    dismissed_by TEXT NOT NULL DEFAULT '',
    PRIMARY KEY (project_no, alert_type)
);
```

### 7.2 聚合算法（`collectAllAlerts`）

1. 从 DB 加载全部项目，通过 `FormulaEngine` 计算派生字段
2. 调用 `StockValidation` 检查 R/S 列预警
3. 批量查询当年全部工时记录，按项目构建 `timesheetStats`
4. 调用 `ProjectAlerts` 检查完成额 vs 工时预警
5. **加载 `project_alert_dismissals` 表，过滤已忽略的预警**
6. 与 DB 同步（事务）：新→active / 已有→更新 / 不再→resolved
7. 返回全量列表与统计摘要（含 `dismissedCount`）

### 7.3 板块名称解析

`sectorCode` 取自 `project.unit_code`（如 `S520`），通过内置 `SECTOR_NAMES` 字典映射板块中文名（与 `sector-workflow.js` 一致）。

```
GET /api/admin/alerts?year=2026&monthIdx=4
```

## 10. 边界条件

| 场景 | 行为 |
|---|---|
| 空表首次打开 | 自动计算并写入全部活跃预警 |
| 重复打开 | 不产生重复记录（UNIQUE + ON CONFLICT） |
| 已忽略预警条件重新出现 | 不会出现（dismissals 表过滤） |
| 已消除预警条件重新出现 | 重新激活，`firstDetectedAt` 重置 |
| 重复忽略同一预警 | 不报错（幂等） |
| 项目号不存在 | 预警仍保留历史记录 |
